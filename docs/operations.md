# 運用：役割 × 時間軸

初回に一度動かして終わり、にしないための考慮表。空欄なく埋まっていることを確認してから使い始める。

## 役割

| 役割 | 主に使うもの | 何をする人か |
|---|---|---|
| 閲覧者 | `jp1-telemetry.html` | 運用担当・性能分析者。ログを開いてピークと長時間ジョブを見る |
| レポート担当 | `tools/jp1_concurrency.py` | JP1 に分析ジョブを登録し、日次レポートを残す |
| 保守者 | このリポジトリ | 判別ルールや計算を直し、テストを通して配布する |

## 格子

| 時間軸 | 閲覧者 | レポート担当 | 保守者 |
|---|---|---|---|
| 初回 | HTML をダブルクリックして、サンプルで画面の読み方を確認する。次に自分のログを読み、「列の割り当て」の自動判別が正しいかをプレビューで確かめる | 手元で CLI を 1 回実行し、`report.md` の列割り当て行と除外件数を確認する。合わなければ `--map` を決める | 実ログのヘッダ行（数行）を `tests/fixtures/` に追加し、判別とテストが通ることを確認する |
| 2 回目以降（日次） | 業務日を切り替えて前日と比べる。ヒートマップで曜日・日付の偏りを見る | JP1 の日次ジョブネットの最後に後続ジョブとして登録する（`--day` に当日の業務日、`--out` に日付フォルダ）。終了コード 0 以外は通常の異常として扱う | — |
| 差し戻し（読めない・おかしい） | 除外理由と行番号を見る。文字化けなら文字コードを Shift_JIS に、列違いなら手で割り当て直す | 終了コード 2 は「開始・終了の列を判別できない」。`--map` を足して再実行する | 実ログの書式を fixtures に追加し、JS と Python の両方を直して突合テストを通す |
| 途中中断 | ブラウザを閉じても失うものはない（読み込み直せば同じ結果）。必要な図は先に PNG 保存しておく | 再実行すれば同じ出力で上書きされる（冪等）。中途半端な出力フォルダは消してから再実行してよい | — |
| ツール更新 | 新しい HTML に差し替えるだけ（設定は保存していない） | CLI を差し替えたら、前日分を新旧で実行して `report.md` を比べる | `tools/embed_samples.py --check` と全テストを通してから配布する。計算を変えた場合は README の実測値も更新する |
| 棚卸し（月次など） | 張り付き時間・長時間ジョブ上位の推移を見て、起動順・多重度上限・ジョブ分割の見直し候補を出す | レポートの保存期間を決め、古い日付フォルダを整理する | 判別できなかった書式の問い合わせを集約する |
| 肥大（ログ・ジョブ数の増加） | 数万行は問題なし（52,700 行で読込 2.4 秒）。重いときは業務日単位でログを分けて開く | `--day` で 1 晩に絞って実行する。全期間の集計は月 1 回など頻度を下げる | 計測（README「規模と速度」）をやり直し、閾値を超えたら描画の間引きを検討する |
| 引き継ぎ | README の「使い方（利用者目線）」と、画面の「指標の定義と読み方」を渡す | JP1 の登録内容（コマンド行・`--limit`・`--map`）を引き継ぎ資料に書く | `docs/requirements-checklist.md` と本表を渡す。計算は HTML と Python の 2 箇所にあることを伝える |
| 撤退 | HTML を消すだけ。データは外部へ送っていないので残留物はない | JP1 から分析ジョブを外し、レポートフォルダを保存または削除する | リポジトリをアーカイブする。出力 CSV は汎用形式なので他の道具へ移行できる |

## 判断が要るところ

- **多重度上限の値**：実行ログからは分からない。実行先ホスト／エージェントの同時実行数の設定値を、運用担当が確認して入れる
- **長時間のしきい値**：「分以上」は運用ルール（例：20 分）と合わせる。「上位％」は日ごとの相対比較に向く。どちらを使ったかはレポートと凡例に出る
- **枠待ちの疑いは推定**：起動順や優先度を変えるといった判断に使う前に、JP1 側の待ち状態の記録や起動可能日時と照合する
